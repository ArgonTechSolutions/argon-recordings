# In-app report generation

Argon Recordings has a separate **Reports** tab for each ready recording. A selector opens one saved document at a time. **New** offers Summary, Action list, Visual report and Custom request, with optional focus, language, visuals and source range. Text summaries/actions start without visuals; Visual report enables them, and the user can change the checkbox. **Refine** supplies the selected draft as context and creates a separate report; it never overwrites or automatically reviews the original. Stale reports require fresh generation.

Custom request requires **What should this report do?**, independently of the optional **Anything to focus on?** field. Submission shows Sending, then queued/running status; completion opens the saved draft. Rejected submissions keep the modal and its inputs with an error. Known output-token exhaustion receives one visible recovery attempt with a larger output allowance, with both calls charged and every configured hard limit rechecked. Unknown incomplete responses, content filtering, refusals and ambiguous network failures are not replayed. Background failures remain visible with the estimated API usage and an explicit edit/retry action; they do not automatically repeat paid calls. Loading and action failures are shown in the Reports panel.

Time inputs accept fractional source seconds without rounding the recording duration. The form reports invalid ranges visibly, including when the range controls are collapsed. This avoids native hidden-field validation silently blocking recordings whose duration is not a multiple of 0.1 seconds. The same precision applies to speaker ranges, marks, visual extraction and analysis ranges. Passage-boundary expansion preserves the requested video bounds, including silence before or after speech.

Desktop shows a compact source panel beside the document. Mobile starts with the source collapsed above the document; a citation opens it at the referenced moment. Source audio and report clips pause each other. Screenshots appear alongside the sections that cite them. Existing transcript correction, speakers and visual tools remain in the Transcript tab. Import is under More options.

## Execution and evidence

The coordinator uses the OpenAI Responses API with two models: `gpt-6-luna` reads the selected transcript and writes internal summaries; `gpt-6.1-terra` reasons over those notes and canonical supporting passages to write the user-facing report. Sol is not called. Both use standard service tier and `store=false`; Luna uses no reasoning and Terra uses low reasoning effort. No API key is sent to browsers or transcription workers. The provider boundary is implemented using the already pinned HTTPX dependency. No remote MCP exposure or public recording URLs are required.

The model can read canonical transcript pages, list registered visuals, inspect actual JPEG pixels, and request screenshots or clips through the existing bounded visual worker queue. Every operation is scoped to the recording and rechecks current requester membership. Visuals can be disabled for a run. Images sent to OpenAI are logged by registered ID/hash, not by pixels or storage paths, in the local run's tool trace. Source text, images, speaker labels and previous reports are untrusted data, not instructions.

The API verifies source/transcript/speaker/annotation revisions, canonical passages, supplied-image IDs/hashes, scope, explicit assignment quotes and report collection revisions. Extraction versions can advance during a run so its own derived media can be used. The final report must reference the current extraction snapshot. Generated reports are always drafts. Review remains an explicit editor action and is not a model-quality guarantee.

A model-supplied `inspected` assertion alone is insufficient: image citations must belong to the set actually supplied to that run's model requests. Full transcript coverage requires all scoped passages to have been retrieved. These controls establish evidence availability and structural/literal consistency, not semantic truth or proof of model attention.

`argon-summary-v1` remains accepted. `argon-summary-v2` adds up to eight `video_references`, each attached to a report item and bound to a registered asset, source hash, media SHA-256 and actual interval of at most 30 seconds. Clip playback checks the saved hash and current project access. Video references are playback aids; the model assesses still frames and transcript, not native video. ZIPs include the references, captions and intervals, but omit video bytes. Selected JPEGs retain the existing portable export behavior.

## Runtime configuration contract

- `OPENAI_API_KEY`: private coordinator process environment, or
- `RECORDINGS_OPENAI_KEY_FILE`: private regular file, up to 4096 bytes, containing the raw key or one `OPENAI_API_KEY=...` assignment. Symlinks and group/world-readable files are rejected. The coordinator process must be able to read the file. The application does not automatically load developer env files.
- `RECORDINGS_AI_BUDGET_USD`: application-wide estimated USD allowance, default **10**, range 0–1000. This is an advisory monthly cost guideline; exceeding it shows a warning and does not prevent or interrupt generation. Zero disables generation by default; a saved administrator configuration takes precedence. The accounting period is the UTC calendar month, independent of the provider's credit renewal date.

This feature is disabled without a key. The Docker installer accepts an opt-in `[ai]` table in `recordings.toml`: `key_file` is a private existing file path (relative to the installation directory or absolute), and `budget_usd` defaults to 10. The file is bind-mounted read-only at `/run/openai/key` only in the API container; only its path and budget are environment metadata. Worker-only configurations reject `key_file`. The installer never reads, creates or changes the secret file. A rootful Docker deployment uses container UID 10001, so the operator must provision a private file readable by that UID; rootless deployments require their corresponding UID mapping. No secret mount is added by default. Deployment configuration and server secret placement are separate operator actions. Env files are excluded from Git and Docker build contexts.

## Administrator controls

**Administration → AI reports** adds an enable switch and optional per-report and monthly soft/hard USD limits. Blank means no limit; a soft limit cannot exceed its matching hard limit. Until an administrator saves controls, the deployment allowance remains the monthly soft guideline and hard limits are unset.

Soft limits alert users and instruct the models to finish concisely while skipping more visual research. Luna still reads the complete selected transcript; a soft limit does not silently skip source passages. Pending conservative call reservations do not trigger a soft warning; completed estimated charges and uncertain charges do. Hard limits atomically compare the conservative next-call bound with per-report and monthly cost. They can stop a run before a draft is saved. In-flight calls complete and reconcile; limits are based on the application ledger, not the provider invoice or credit account. Each call is assigned to its UTC admission month, including runs crossing month-end. Historical costs from before this ledger retain their original job month.

API-key replacement/removal uses the existing administrator session, MFA freshness and CSRF checks. The password field is write-only and cleared after submission; responses and audit events contain configuration metadata only. An administrator key takes precedence over the existing deployment key. Removing the administrator override falls back to that deployment key, if present, without changing its read-only mount.

The administrator key is stored at `/data/ai-private/openai.key` in the coordinator data volume (directory 0700, file 0600, application-owned), separate from SQLite. Atomic replacement and no-symlink/private-file checks protect local access. It persists across restarts and is included in private data-volume backups; handle those archives as credentials. No secret is automatically provisioned by installing this feature, and saving a key does not issue a provider request. Limit and key changes apply before the next paid call without a service restart. Accounts mode is required for these admin routes.

## Bounds and recovery

Two jobs may be queued/running across the instance, one per recording. The form obtains a free local cost estimate based on source size, cached reading batches and opt-in visuals. It shows an indicative range, not a guaranteed quote or spending cap. Pending estimates and measured estimated usage contribute to the monthly warning. No hard cost limit applies until an administrator explicitly configures one. Configured hard limits are enforced before each paid call; otherwise the allowance remains a soft guideline. Provider-side quotas and limits still apply.

The entire selected transcript is automatically sent to Luna in roughly 24 KB source batches. Long passages are fragmented without dropping text. Luna receives short request-local passage IDs rather than copying long UUIDs. The structured-output schema enumerates the exact allowed short IDs for each reading/consolidation batch. Returned IDs are also checked against the server allowlist and mapped back to canonical source IDs before caching; one explicit corrective attempt can repair invalid internal references, with all usage charged. Notes are compacted hierarchically before Terra sees them. Successful internal readings are cached in the coordinator database against recording identity, source/transcript/speaker/mark revisions, language, model and prompt version; added extraction assets do not invalidate transcript readings. Source changes invalidate reuse. These internal notes are not published as reports. A new explicit retry can reuse completed readings, while ambiguous provider calls are never automatically replayed.

There is no recording-duration, transcript-page count or six-minute whole-run cutoff. Progress identifies the current reading batch and writing phase. Optional evidence gathering finishes with available evidence after five rounds, rather than failing at the former step ceiling; unavailable derivations are disclosed. Response size, per-request network timeouts, image/media bounds, permission/cancellation checks and canonical evidence validation remain in force. Invalid provider output can still fail visibly. Reading and writing output allowances are 8192 and 12000 tokens respectively; these are output ceilings rather than target lengths. A fully received `incomplete/max_output_tokens` response with valid usage can receive one larger-allowance completion attempt. All usage is retained and hard limits are rechecked. Other incomplete reasons are reported explicitly without replay. Uncertain calls retain a conservative precharge; successful calls reconcile per-model token usage. Restart marks in-flight work failed rather than replaying paid calls; queued work can resume. Reviewed reports and transcription data remain untouched.

Transcript ranges expand to containing passage boundaries while preserving requested video bounds. The writer receives compact internal notes and bounded canonical excerpts, with additional evidence tooling for opted-in visuals. Summarization can omit details; these checks establish evidence availability and literal consistency, not semantic correctness.

Cost estimates use conservative standard input/cache-write and output rates per million tokens: Luna **$0.125 / $0.50**, Terra **$1.25 / $5.00**, verified against the [Luna](https://developers.openai.com/api/docs/models/gpt-6-luna) and [Terra](https://developers.openai.com/api/docs/models/gpt-6.1-terra) references. Ordinary uncached input is $0.10 and $1.00 respectively; discounted input may therefore cost less than the ledger estimate. The estimator assumes typical output lengths and optional tool work; actual cost may fall outside its displayed range. This ledger is not the OpenAI invoice, credit balance or organization-wide spending limit. Pricing changes require revalidation.

## Validation boundary

`backend/tests/test_report_generation.py` substitutes only the provider transport and exercises the real routes, storage, tool inputs, image bytes, reports, budgets, permissions, cancellation, refinement and export paths. `scripts/report-browser-check.mjs` uses the real application with the explicitly synthetic upstream in `scripts/report_browser_app.py`; it exercises generation, mobile layouts, document switching, source navigation and cancellation without paid requests. The browser fixture is not an application entrypoint.

The two-model regression includes a 1,200-passage hour, all-source reading, hierarchical compaction, cached second generation, source-change invalidation, per-model accounting and optional-tool finalization. A real API smoke check used a synthetic hour with 600 passages: seven Luna calls and one Terra call saved a six-item/six-citation draft for $0.022606 estimated measured usage, against a $0.0356 estimate. Costs on real recordings depend on their content and the requested output.

The existing visual-browser check retains real FFmpeg fixture publication, cross-tab review/staleness and offline export checks. A separate live smoke check used a tiny synthetic English transcript, created a cited action draft using the real OpenAI API and recorded estimated cost around $0.01. A second real API smoke check supplied an actual synthetic color-pattern JPEG through the image tool; the model described the visible bars/stripe and saved one selected image in an unreviewed cited draft, at an estimated $0.016 for that successful run. Representative private-recording quality, adaptive selection on real footage and deployment acceptance remain separate from these local checks.

Administrator/recovery validation also covers MFA/CSRF, private write-only key persistence/removal, concurrent hard-limit admission, pending versus uncertain charges, UTC month rollover, output-token recovery for both models, strict local-to-canonical ID mapping and non-recoverable responses. A real API test on a synthetic Spanish hour (600 passages) saved a seven-item/six-citation draft at $0.032321 estimated measured usage, versus a $0.0386 estimate. No private recording or production key configuration was changed by these tests.

Failed internal-reading diagnostics distinguish invalid source IDs from Pydantic format/size constraints. Only field paths and validation type codes are retained in the job trace, not generated or source text. Valid cached notes remain reusable when the schema constraint changes.
