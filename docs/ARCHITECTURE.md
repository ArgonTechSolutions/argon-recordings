# Foundation architecture

The coordinator is the only writer to its local SQLite database. Remote workers use HTTP; never share the SQLite file over a network filesystem.

1. A project owns recordings. Creating a recording reserves metadata and an unclaimable job.
2. The source is streamed to a unique staging file under a byte/disk limit, hashed, fsynced, and moved to its generated source ID. Only then is the job queued. A failed upload is retryable; original client filenames are never storage paths.
3. A worker claims one job under an immediate SQLite transaction. The current implementation permits one valid active lease globally. Lease IDs fence heartbeats, source reads, artifact writes, failure and completion. Leases last 120 seconds; the worker renews them every 20 seconds. Repeated lease loss is bounded to three claims.
4. Source bytes/hash are verified at the worker. FFmpeg probes and bounds decoding; Turbo produces source-relative timestamps. Frames are sought explicitly at 0, 15, 30… seconds, not inferred from a variable-frame-rate proxy.
5. Artifacts are uploaded into a job/lease-specific directory. They are not exposed to the browser until completion validates the manifest and commits transcript, index and artifact references atomically. Completion retries with the same body/lease are idempotent. Stale or changed publications are rejected.
6. The UI queries ready media and transcript routes; original sources are worker-only. SQLite FTS5 is project-scoped and receives quoted terms rather than raw query syntax. The coordinator also stores timestamped chunk vectors in SQLite. A pinned local ONNX model embeds passages/queries with E5 prefixes and masked mean pooling; normalized dot products provide exact cosine rankings. Hybrid retrieval fuses these with FTS5 ranks. No generated answer or agent is required.

`recordings.sqlite`, `sources/`, and accepted artifact paths under `results/` are authoritative. `staging/` and unpublished artifact remnants can accumulate after failed jobs; automated garbage collection and quotas beyond upload/disk reserve are not implemented yet. Do not delete them blindly while processing. No automatic original expiry/pruning runs. New embedding/correction tables and an index are created additively for foundation databases; existing tables are not rewritten. Unknown versions fail closed.

The first profile is intentionally single-user on loopback. Worker bearer credentials do not authenticate browser users. Uploads, media decoding, model runtime, browser access and worker publication are separate trust boundaries. No Docker socket is mounted in application code, no remote URLs are ingested, and no credential is generated. Public/team deployment needs further authentication, per-project authorization, storage policy, decoder isolation and release qualification.

The first functional tests substitute only inference/extraction where documented; live Chromium checks exercise actual API, SQLite search and file serving with synthetic data. None of these tests qualifies real speech inference through a remote deployment.


## Search and correction state

Embedding inference is serialized, CPU-only, two threads and batches of four. Windows are 220 tokens with 40-token overlap, with source intervals inherited from intersecting transcript segments. Publication/acceptance schedules a post-response index refresh; search rebuilds missing/incompatible indexes after an interruption. Index publication compares a transcript fingerprint under a transaction to reject concurrent edits. Acceptance removes the old vectors/version in the same transaction as the text/FTS update. Each project is bounded to 200 recordings and 10,000 chunks; a transcript indexing budget of 250,000 characters prevents unbounded tokenizer work. Query vectors use a bounded in-memory cache; documents persist across restart. The first query can pay loading/indexing latency.

Corrections reference stable segment IDs and capture original text plus a bounded user hint. Candidate discovery uses accent-insensitive phrase-window spelling similarity, scoped to one recording. User selection is required; no global text replacement happens. One correction task per selected segment has a 120-second renewable lease and a three-claim limit. Correction and original ASR claims exclude each other's active leases globally. A retry reads retained mono PCM audio, crops the selected interval, supplies a Turbo prompt/hotwords, and restores absolute timestamps. Completion accepts only bounded, time-ordered proposals inside the selected interval; duplicate identical publications are idempotent. Acceptance checks the captured original text, preserves correction history, and invalidates search atomically. Dismissal fences in-flight results. A failed retry leaves the ready transcript usable.

The backend-choice measurements and model limitations are recorded in [EMBEDDING-EVALUATION.md](EMBEDDING-EVALUATION.md). Persistent services, deployment, and Philemon model timings remain outside local validation.
