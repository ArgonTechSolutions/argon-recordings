# Local model storage

Storage audit: 2026-10-23. This describes the development checkout on Vulcan; it does not verify or change the installed Philemon configuration.

Reverified on 2026-10-26 at application commit `370d184`: all 19,701 protected files and all nine retained model files still match the saved SHA-256 manifest. All 23 successfully removed targets remain absent. No additional files were deleted during this verification. The prior cleanup recovered 6,107,062,272 allocated file bytes (5.69 GiB); current allocated directory sizes are 2,937,065,472 bytes for `models` and 344,625,152 bytes for `.recordings`. The small model-tree increase since cleanup is retained development material. The reference still selects E5-large, no main `recordings.toml` or runtime model/data environment overrides were present, and the redundant float segmentation file remains permission-blocked as described below. The root filesystem currently reports 119 GiB used and 95 GiB available; its changes also include other projects and are not attributable to this cleanup.

## Models to retain

| Location | Purpose | Keep |
| --- | --- | --- |
| `models/turbo` | Curated large-v3-turbo transcription; CPU INT8, two threads | Required for transcription and installation qualification |
| `models/e5-large` | Quantized multilingual E5-large, the installer/reference configuration's selected retrieval profile | Required for the selected semantic-search profile and its integration tests |
| `models/diarization-evaluation/embedding.onnx` | Frozen ERes2Net candidate used by the optional diarization runtime | Keep while speaker integration/qualification continues |
| `models/diarization-evaluation/sherpa-onnx-pyannote-segmentation-3-0/model.int8.onnx` | Pinned INT8 segmentation used with that candidate | Keep with its license/provenance files |

No application instance or container mounted these paths during the audit. There was no main `recordings.toml`, and the current shell had no runtime model/data overrides. The reference configuration selects Turbo and `embedding = "large"`; retained installation-smoke configuration also selects large and reuses the same Turbo directory. Direct API startup without an embedding directory uses keyword search rather than automatically loading a downloaded model. These are configuration/source facts, not proof of a running service.

The diarization candidate is still **quality blocked**; keeping its weights is not acceptance or automatic activation. Its exact two required files are listed in `backend/argon_recordings/diarization_runtime.py`. Do not confuse these small weights with the multi-gigabyte evaluation corpus archive.

## Downloads removed after dependency checks

- `models/e5-base-fp32`: completed full-precision comparison; not a selectable installer profile and not referenced by the selected configuration.
- `models/e5-base` and `models/e5-small`: optional quantized alternatives from the completed retrieval comparison. Neither is selected locally. Their supported profiles remain in source; removing downloads does not remove the feature.
- `models/diarization-evaluation/wespeaker_en_voxceleb_resnet34.onnx`: completed alternative-model comparison; not the application's pinned candidate. Reports, hypotheses, references and audio excerpts remain available. Rerunning inference for this alternative requires downloading its documented, checksum-pinned model again.
- `models/diarization-evaluation/voxconverse_test_wav.zip`: verified against the publisher's MD5 before removal. The evaluation excerpts were already extracted; saved audio, RTTMs, manifests, metrics, licenses and provenance were preserved. The full archive is only needed to select new excerpts.

See `EMBEDDING-EVALUATION.md` and `DIARIZATION-EVALUATION.md` for the completed comparisons and model provenance. No recordings or model weights belong in Git.

The segmentation directory also contains a redundant float `model.onnx` (5,992,913 bytes). Application and evaluation scripts use the INT8 file. The float copy was preserved because it and its parent are owned by UID 65534; deleting it requires an independently authorized ownership/privilege fix. No sudo or ownership changes were made.

## Test data and preservation

`.recordings` is not a cache directory. It contains SQLite databases, installation metadata, authentication fixtures, logs, screenshots and a deployment public key. The audit preserved these except for 18 specifically verified disposable `pytest-*/test_long_completion_and_audio0` cases. Each removed case had no users, sessions or invitations, a source equal to the test's literal synthetic payload, and the exact 13 MiB zero-filled WAV-shaped artifact generated by that test. These were completed test fixtures, not user recordings. The remaining directory was retained.

The cleanup also preserved the MCP validation environment and browser/FFmpeg fixtures needed by unfinished feature work. Detailed deletion manifests, retained-file checksums and measurements are local under `models/validation/storage-maintenance/`; they are ignored by Git and may include private local paths. Do not copy their raw contents to shared knowledge.

## Regeneration

Preparation is explicit and checksum-verified; runtime inference never downloads models. With the normal backend dependencies available:

```sh
PYTHONPATH=backend python scripts/prepare_embeddings.py models/e5-base base
PYTHONPATH=backend python scripts/prepare_embeddings.py models/e5-small small
PYTHONPATH=backend python scripts/prepare_embeddings.py models/e5-base-fp32 base-fp32
```

Download an alternative only when a configuration change or a new comparison requires it. Keep reports and frozen references independently from regenerable distribution archives.
