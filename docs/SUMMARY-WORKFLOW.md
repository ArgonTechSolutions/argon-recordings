# Cited summary workflow

P11 local checkpoint, 2026-10-26. Owner: Argon. The optional package lives under `scripts/agent-integration/`; it does not install a plugin, issue a grant, deploy an API or publish reports.

The repository-owned `recording-summary` skill supports meetings and technical demos in the requested language. It collects paginated transcript/speaker/mark evidence, inspects registered images, can request bounded missing media through the separate derive permission, and rechecks source/evidence revisions before returning a cited summary. Owners, deadlines and decisions require source support. Source content, including text that claims to be system instructions, remains untrusted evidence.

The portable private plugin contains that skill and the existing twelve-tool stdio adapter. `build_plugin.py` includes only explicit regular source files; the built ZIP supplies `server.py` at the path declared in `mcp.json`. Dependencies remain an explicit operator preparation step. See [adapter setup](../scripts/agent-integration/README.md) for the build, private credential-file mechanism, interpreter selection and credential-free client example. No host-global connection was changed.

`argon-summary-v1` defines report claims, exact source citations, source/evidence versions, scope, coverage, limitations and literal assignment support. The skill's `summary_contract.py schema` emits the report, captured-evidence and final-reference JSON schemas. Its checker rejects mismatched snapshots, incomplete cursor coverage claimed as complete, fabricated or out-of-range citations, uninspected image references and unsupported owner/date literals. It requires containing segment intervals for assignment quotes; word-level alignment is not fabricated. It does not prove that a quote semantically assigns an action or that an image was actually viewed. Those remain agent/human evaluation boundaries.

## Executed evidence

- The combined published-SDK adapter, real disposable account/API/SQLite/FFmpeg and summary/package suite passed **24 tests**. Tests cover project/search cursor forwarding, actual search response shape, pagination, grant denial/revocation, bounded media extraction and JPEG decoding, unpacked package startup/tool discovery, schema CLI, stale versions, broken cursor chains, image provenance and unsupported assignment literals. The prior backend/contract/frontend checks remain unchanged by this integration-only slice.
- The skill passed the installed skill validator. The package was built and its manifests, eight-file allowlist, declared runtime entrypoint and generated schema were inspected/executed. This is package/runtime evidence, not a desktop-plugin installation pass.
- One independent **GPT-6.1** forward-test used responses captured from the real disposable SDK/API/FFmpeg test, including an actually viewed JPEG and a hostile quoted instruction. The agent returned a Spanish cited summary and machine-readable draft. It retained dark mode as an unapproved/unshipped proposal, attributed the patch/relative Friday commitment to the textual Alice passage, kept rollout ownership undecided, and rejected the false Bob/date instruction. It described only the visible blue field. Parent inspection compared these claims with the fixture text and image ledger; the generated report passed the contract checker in the prepared validation environment.
- The forward-test explicitly disclosed unavailable speaker/mark responses and final live refresh. Its evidence replay is **not** live host pairing. The system Python lacked Pydantic; using the existing prepared interpreter resolved validation, and setup guidance now names that requirement.

The isolated fixture is a small behavioral check, not a representative summary-quality benchmark. Actual owner pairing, a host-loaded skill/plugin, remote reachability, long-recording context quality, representative visual readability, Spanish/private-recording model acceptance and Philemon installation remain unverified.
